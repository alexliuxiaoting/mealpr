## 踩坑记录（可复用）

1. 同一文件的**并行 Edit 会互相覆盖**（本次丢了 4~5 处修改）→ 同一文件务必串行编辑或整文件重写。
2. npm 安装在沙箱下写不了 `~/.npm/_cacache`（EACCES），用 `/tmp` 缓存会被 SIGTERM →
   改用工作区内缓存：`npm install --cache ./.npm-cache`（已加 .gitignore）。
3. TS Node ESM：`module` 与 `moduleResolution` 必须同时为 `NodeNext`；相对导入要写 `.js` 后缀，
   `src/` 根目录下不能写成 `../types.js`。
4. esbuild 的 `banner` 不要再加 shebang，入口文件自带会变成双 shebang → `SyntaxError: Invalid or unexpected token`。

## MealPR v1.1.0：真机验证后修复套餐缺陷 + P1 页面

- **真实缺陷（T13）**：`plan.mjs` 把套餐并进主食池（`mainPool = [...combos, ...mains]`），
  再统一叠加「主食+饮料+小食」，导致「酥脆无双套餐 + 可乐 + 苹果片」——套餐本身已含炸鸡/迷你薯条/无糖可乐，
  **重复计价且审核者看不出来**。修法不是加 if 而是改数据模型：`MealItem.comboComposition`
  （`components[] + source: 'mcp-detail' | 'unknown'`），套餐单独走一条候选路径，
  组成未知→只出套餐不叠加；新增阻断校验 `combo-composition-verified`；
  `portions-adequate` 改按组成内主食计数，未知时降级 UNKNOWN。
- **三条 API 事实订正（T14）**：①价格字段是 `currentPrice`/`originalPrice`，不是 `price`；
  ②`query-meal-detail` 参数是 `code`，传 `productCode` 返回 400；③`calculate-price` 单位是**分**
  （2290 = ¥22.90）。第四条：早期文档说「官方未公开 inputSchema」是**错的**，`tools/list` 会返回完整 schema。
  四条固化进 `src/mcp-adapt.ts` 的 `MCP_FIELD_FACTS` 由测试断言；新增 `scripts/mcp-adapt.mjs` 做归一化（只告警不补数）。
- **P1 页面**：`npm run site` → `dist/mealpr-review.html`（单文件 212KB）。刻意不用 Vite/React——
  内联 esbuild 把 `src/web-entry.ts` 打的 IIFE，**就是 Skill 用的那份核心**，所以 Approve 跑真实状态机、
  指纹浏览器内计算、DEMO 必然被闸门拒绝。为此把 `fingerprint.ts` 的 `node:crypto` 换成 `src/sha256.ts`（纯 JS SHA-256），
  并写 `scripts/smoke-site.mjs` 在 `vm` 里跑页面那份 bundle 断言与 Node 一致。
- **状态**：`npm test` 10 文件 120 项通过；`npm run typecheck` 0 error；`smoke:site` 全绿；
  `dist/mealpr-skill-v1.1.0.zip` 254KB。新增 fixtures `demo-combo.json`、`tests/combo.test.ts`、`tests/mcp-adapt.test.ts`。
